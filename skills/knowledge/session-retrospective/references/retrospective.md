# Evidence-led improvement and learning

Review navigation friction, unavailable runtime evidence, repetitive expensive calls, missing/unwired checks, conflicting/no-op instructions and review failures. Find the existing guardrail before proposing a duplicate. Mechanical failures deserve deterministic checks where practical; contextual judgment belongs in focused reviewer guidance.

A learning entry captures context, root mechanism, transferable rule and recognizable signal: “When I see <evidence>, I will <action>.” Search existing lessons first; merge the same mechanism with a new example. Do not generalize one anecdote into a universal coding prohibition.

Optional output reflection examines accuracy, completeness, clarity, actionability and concision using evidence, not confidence rhetoric. The imported evaluator applies text heuristics only: claims of successful tests can affect its score without establishing those tests ran. Use it to suggest manual review, never to declare correctness or block every task automatically.
