# Solution Discovery

Search the existing codebase first, then available registries, official packages, GitHub and configured skill/MCP sources. Check tool/auth availability and report skipped channels rather than claiming complete search.

For a small need, search inline. For a nontrivial integration, the [research specialist](../../../support/knowledge/agents/researcher.md) can compare sources independently. Examine license, maintenance, runtime/version compatibility, trust boundary, dependency footprint and actual capability. Popularity is evidence of adoption, not fitness.

Return a short adopt/extend/build comparison: candidate, proven match, missing behavior, cost/risk and recommendation. Prefer an established repository convention over creating a second architecture. Search findings do not authorize installing a package, starting an MCP server or sending code externally.

Handoff evidence to requirements/planning or implementation as appropriate. Use [technical research](../technical-research/SKILL.md) for source verification.
