# Codebase Onboarding

Start broad but shallow: manifests, README/instructions, source layout, build/test configuration, entry points and relevant recent history. Skip unavailable Git evidence honestly. Trace a representative real execution path before describing architecture.

Produce a useful map: purpose/stack and exact supported runtimes; major responsibilities and ownership; entry points and important flows; tests/build/run commands; conventions supported by examples; known limitations and starter tasks. Read [localization and convention evidence](references/localization.md) when delegating exploration.

Save a requested guide under docs/knowledge/onboarding.md. Propose concise harness navigation pointers only when setup is requested; do not silently write global settings or invent a CLAUDE-only installation. Exploration is read-only; onboarding does not authorize refactors.

Use the adapted [repository explorer](../../../support/knowledge/agents/repo-explorer.md) for bounded fact localization when available. For a guided CodeTour artifact use [code tours](../code-tours/SKILL.md).
