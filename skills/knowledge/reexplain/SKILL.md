# Reexplain

Stop advancing the task long enough to explain where the discussion is and why the last point matters. Use short concrete sentences and familiar words. Preserve the actual technical distinction instead of merely shortening it.

Use the project's confirmed domain vocabulary when available, defining an unfamiliar term at first use. State the intended outcome, current finding and next step. An example or small diagram can clarify a relationship; do not create a new artifact or lecture by default.

Then resume the active task unless the user asked to stop. This is an explicit communication repair, not a persistent compressed-response persona.
