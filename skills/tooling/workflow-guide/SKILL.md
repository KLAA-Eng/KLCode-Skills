# workflow guide

Start with the user's current outcome and existing artifacts. Distinguish requirements, planning, implementation, verification, review, release preparation and execution; do not run them all because a tool is available. Directly answer simple routing questions.

Read [workflow routing](references/workflow-routing.md) when the lifecycle is unclear. Use canonical skills by their actual paths. Plans have one authoritative ledger and defaults docs/specs/, docs/plans/, docs/decisions/, docs/knowledge/ only where the project has no established equivalent. Multi-session planning remains separately callable.

At a phase boundary, [context transitions](references/phase-boundaries.md) compare continuing, deliberate compaction, handoff or selected delegation. Prefer preserving relevant rationale; do not assume a fixed model context size or claim summaries are lossless. Existing session authorization carries forward.

Recommend the smallest useful next workflow and explain the expected deliverable. Loading a guide does not authorize cloud tools, persistent memory, review teams, autonomous operation, installation or remote writes. If the user asked to do the work and scope is clear, continue through the appropriate canonical workflow rather than stopping at a menu.
