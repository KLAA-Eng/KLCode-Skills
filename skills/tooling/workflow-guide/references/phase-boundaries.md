# Context transitions at phase boundaries

Adapted from Matt ask-KLCode/PHASE-BOUNDARIES.md.

Continue when the next phase needs this phase's primary evidence/rationale and context still fits. Relevant original reasoning is often more useful than a lossy summary, particularly requirements → implementation.

Clear context only when it is truly disposable and the host supports that action. A clean window cannot recover discarded rationale merely by reading the final diff.

Create a portable handoff when changing harness/repository/person or handing a bounded side task to someone else. Include accepted objective, decisions, permissions, artifact paths, evidence, current state and outstanding work; do not duplicate the entire transcript.

Delegate when the task is isolated and selected for another agent's context. Give raw artifacts and contracts rather than a preferred conclusion. Compaction is appropriate when relevant context must be retained but no longer fits; seed the next phase's important constraints. Treat the summary as secondary evidence and verify uncertain details.

No fixed '150k smart zone' or automatic host command is universal. A context operation does not cancel an active task or revoke carried authorization. Preserve the latest steering and remaining objective across transitions.
