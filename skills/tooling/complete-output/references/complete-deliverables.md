# Complete requested artifacts

Adapted from taste output-skill. This mode is explicitly selected.

List the actual requested deliverables and finish them: complete files, functions, sections, components or answers. Verify resources and runtime dependencies rather than equating a long code block with completion.

Omission markers such as 'rest of code', 'implement here', 'same as above' or 'and so on' must not replace requested implementation. Legitimate language syntax, an explicitly requested sketch, a focused patch, or a quoted example is different from an omission. Do not ban every ellipsis or TODO string in an existing source file mechanically.

For large files, write the requested artifact and test/render/check it as appropriate. The final response can link the result and give concise evidence; no need to reprint all implementation merely to demonstrate length.

When a genuine output limit forces a boundary, finish a coherent artifact unit, record completed/remaining items and precise continuation point, and preserve state. Never claim completeness when some requested artifact is missing. Do not expand a reversible documentation task into a production-critical process or introduce unrelated work.
