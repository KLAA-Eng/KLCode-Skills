# complete output

Apply when the user selects full/unabridged output. Count the requested artifacts and scope; finish each, preserving runnable code, required resources and actual content. Do not replace requested sections with 'similar to above', an implementation TODO, or a promise to continue later.

Read [complete deliverables](references/complete-deliverables.md). Completeness means the requested scope is handled, not that unrelated work becomes production-critical. Concise prose and targeted diffs are still appropriate when the user requested them; legitimate syntax such as variadic ... is not an omission.

Prefer writing large artifacts to their requested files and verifying them rather than exhausting chat output. If a real output limit prevents a single response, stop at a clean artifact boundary, identify exactly what is complete and where continuation starts, and preserve task state. Do not falsely claim the entire result is finished or intentionally withhold available work.

This mode is explicitly selected; it does not override unrelated task requirements.
