# Adversarial decision council

Use for ambiguous options/go-no-go tradeoffs, not factual lookup or routine code review. Frame one real decision with constraints and success criteria. Record the coordinator's initial position before hearing independent voices so synthesis can acknowledge a changed view.

Use skeptic (premise/simplification), pragmatist (shipping/user impact), critic (failure/downside) plus coordinator/architect. Each returns position, three reasons, main risk and overlooked consideration. Share question and necessary evidence, not the full anchoring conversation.

Show raw positions, consensus, strongest dissent, premise challenge and recommendation. Explain why an external view was rejected and whether it changed the answer. Default one round; further rounds ask a narrower unresolved question. User remains decision authority. Persist only durable changes to accepted project decisions, never every council exchange.
