# Interface variants in realistic context

Default to three structurally different variants, fewer when the choice is narrow. Compare information hierarchy, layout and primary affordance rather than three colors on the same card grid.

Prefer mounting variants into a realistic existing surface with authentic density and surrounding navigation. Use an isolated marked prototype surface only when no host fits. Web experiments may use a variant query parameter and an obvious switcher; desktop experiments can use a local toggle, separate windows or image comparison appropriate to the framework.

Preserve existing data/auth behavior unless the question explicitly concerns it. Use safe representative data and keep the switcher out of production. Each variant should show its current identity and relevant state.

Collect a decision with rationale: chosen direction, borrowed elements, rejected tradeoff and unresolved questions. Remove or isolate discarded variants once evidence is captured. Production conversion is a separate implementation task.
