# Decision map

Destination: what becoming clear means, not a general aspiration.
Standing notes: scope, constraints, selected workflow references.
Decisions so far: named answer, one-line gist, evidence/detail pointer.
Live questions: stable ID, title, type, blockers, owner/claim, status and answer pointer.
Not yet specified: in-scope concerns too unclear to phrase precisely.
Out of scope: consciously excluded work and rationale.

Types:
- Research: inspect local/primary sources to establish facts.
- Interview: human preference or tradeoff through grilling.
- Prototype: interactive evidence that discussion alone cannot establish.
- Enabling task: practical work needed before judging an option, not delivery of the whole destination.

A precise question may be blocked and still ticketable; vague future concerns remain fog. Resolve dependencies before promoting a question to the frontier. Do not pre-slice unknown work into speculative implementation tasks.

Name links rather than showing bare issue numbers. When using an optional external tracker, create records first, then wire real IDs in a second pass; placeholder numbers can link unrelated issues. Claim before concurrent work. Store the answer once and let the map remain an index.

After resolution, update the frontier, graduate fog, reconsider invalidated questions and record excluded scope. Research results can be local durable evidence; no automatic branch push is needed.
