# Interface Redesign

This is the explicitly selected visual direction for this surface. Apply its aesthetic rules within that scope; do not combine contradictory alternative styles. Existing brand requirements, truthful content, accessibility and reduced-motion behavior take precedence. Verify fonts, icons, dependencies and assets actually exist; source examples do not authorize installing packages or inventing evidence.

Preserve the existing stack, real content and working behavior. Scan implementation and actual screens, identify problems with user-visible impact, and prioritize targeted changes by benefit and risk. Read [redesign audit](references/redesign-audit.md) for typography, color, layout, interaction/state, component and code checks.

Preserve the established brand unless changing it is the request. Separate a usability defect from a stylistic preference: a data tool may intentionally be dense, use system fonts or show multiple semantic colors. Select one coherent direction before applying decorative upgrades.

Fix broken focus/navigation, contrast, clipping and missing feedback before costly visual effects. Make related hierarchy/spacing/token changes together, inspect their rendered result and exercise affected actions. Reuse interface-development and interface-accessibility for behavior and verification.

Source examples of placeholder metrics, people or photos are illustrative. Do not fabricate testimonials, customer statistics, activity dates or legal content to make a redesign look realistic. Use labeled sample data when the project has no real content.
