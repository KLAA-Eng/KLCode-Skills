# Image To Website

This is the explicitly selected visual direction for this surface. Apply its aesthetic rules within that scope; do not combine contradictory alternative styles. Existing brand requirements, truthful content, accessibility and reduced-motion behavior take precedence. Verify fonts, icons, dependencies and assets actually exist; source examples do not authorize installing packages or inventing evidence.

This is the selected image-first design-to-code pipeline. Confirm an available image-generation tool and requested section scope before generating; do not pretend an image was created when tooling is absent.

1. Build a concept spine, palette/type direction and content sequence from the brief. Read [image-first specification](references/image-first-specification.md) for extraction criteria.
2. Generate large readable section references, normally one per section rather than a compressed tall website board. Use website-design-images as an optional reference-generation helper; do not change to its style without selection.
3. Inspect each image's geometry, hierarchy, spacing, type roles, media treatment, CTA/state and responsive implications. If a needed detail is unclear, generate a fresh section/detail image rather than treating a tiny crop as precise design evidence.
4. Implement the design in real responsive HTML/components, using actual text and interactive controls instead of flattening the entire page into a screenshot. Keep primary content readable on a laptop and phone.
5. Compare real renders to the references, fix material mismatches and verify actions/accessibility. Generated references are direction, not proof of responsive behavior or functional correctness.

Bound extra generations to the requested deliverable and available tool limits. Record missing/failed generations honestly; a style preference does not authorize unlimited service use or additional content. Keep source/reference images alongside implementation evidence as the project convention allows.
