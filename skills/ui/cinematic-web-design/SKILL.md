# Cinematic Web Design

This is the explicitly selected visual direction for this surface. Apply its aesthetic rules within that scope; do not combine contradictory alternative styles. Existing brand requirements, truthful content, accessibility and reduced-motion behavior take precedence. Verify fonts, icons, dependencies and assets actually exist; source examples do not authorize installing packages or inventing evidence.

Use this mode for a deliberately cinematic marketing/portfolio page: AIDA progression, wide editorial headlines, tightly filled grids and GSAP scroll scenes. Do not apply AIDA or pinned scroll sections to an ordinary operations tool automatically.

Read [cinematic specification](references/cinematic-specification.md). Choose a hero, typography, three component forms and two motion ideas appropriate to the real brief. Use [choose-direction.mjs](scripts/choose-direction.mjs) with a recorded seed for an actual reproducible draw; do not simulate tool execution or fabricate random output.

Plan attention/interest/desire/action sections around real content, verify headline wrapping and grid occupancy, then implement using the existing stack. GSAP/ScrollTrigger are optional dependencies requiring project compatibility; @gsap/react only applies to React. If unavailable, report the limitation and use an agreed static/CSS equivalent rather than importing nonexistent packages.

Honor reduced motion by removing pinning, scrubbing, marquee movement and stacked transforms, preserving readable static end states. Keyboard/focus and responsive flow remain functional even where pointer hover is unavailable. Inspect real renders; never guarantee line counts from a CSS class alone.
